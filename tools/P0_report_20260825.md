## 二、改了什么

### 2.1 根因回顾

`_update_distribution` 从当前盘面反推暗子池，逻辑是「初始池 − 盘面上可见的明子」。缺陷在于**被吃掉的明子同样不在盘面上**，于是被计回暗子池。

暗子池是**跨回合状态，原理上无法从单帧盘面恢复**：一个子「曾经被翻开」这件事，在它被吃掉后只存在于历史中，盘面上不留任何痕迹。这是结构性错误，不是参数问题。

### 2.2 新实现：`DarkPoolTracker`（`jieqi_engine.py:764-940`）

事件驱动维护 `rev_ever[类型] = 该类型至今被翻开过几个`：

| 事件 | 处理 | 可观测性 |
|---|---|---|
| 暗子被走动翻开 | `rev_ever[T] += 1`，精确扣减 | 可观测（读落点字符） |
| 暗子仍朝下时被吃 | 按比例缩放全部类型 | **类型永不公开** |
| 链条断开 / 新对局 | 单调下界 + 精确重标定 | — |

两个设计要点：

**① 比例缩放是正确的贝叶斯边缘，不是权宜之计。** 一个未知类型的子离开池子时，在没有任何区分信息的条件下，每种类型按其当前占比承担这次损失 —— 类型比例不变，池和精确减 1。

**② 不变量按构造成立。** `pool()` 最后一步把 base 缩放到 `n_dark`：

```python
base = {t: POOL_INIT[t] - self.rev[mine].get(t, 0) for t in POOL_INIT}
scale = n_dark / total
return {t: base[t] * scale for t in POOL_INIT}
```

即使着法历史完全丢失（识别错/漏回合/换对局），池大小也永远正确，只是类型比例退化回「按剩余先验」—— **不会再出现幽灵暗车**。这是我最看重的性质：它把一个可能静默失真的模块变成了最坏情况有界的模块。

### 2.3 顺带修掉的两处

- **移除 `live` 门控**。原代码裁判模式（下发 `check_state`）走 `live=False` 分支跳过记忆维护，等于 A/B 实验恰好测不到修复。池的正确性是评估正确性问题，与长将链条由谁维护无关，现在两种模式都启用。若不改这一处，本报告后面所有对局数据都会是无效的。
- **`K` 僵尸键**：原 `p in "RNBAKCP"` 会给池塞一个 `K: 0`（帥/將从不入池）。

### 2.4 兼容性

`_update_distribution` 保留为等价重标定（`bench_v2.py` 等工具仍在调用），现在同样满足不变量。

## 三、单元测试（`tools/test_dark_pool.py`，30 项全通过）

| 分组 | 项数 | 关键用例 |
|---|---|---|
| `TestPoolInvariant` | 5 | 全棋谱 4157 局面逐个断言不变量；**并反向断言 v5.11 违反它**（证明测试有区分力，不是恒真断言） |
| `TestRevealEvents` | 6 | 我方/对方翻开识别；暗子走后立刻被吃（信息丢失但池大小仍正确）；断链兜底；单调性；识别错误封顶 |
| `TestProportionalShrink` | 2 | 缩放保持类型比例；翻开+缩放的组合语义 |
| `TestReplayAccuracy` | 2 | 与 v5.11 及 ORACLE 三方对比 |
| `TestBugRegression` | 3 | 残局幽灵暗车；复现日志最坏案例；`K` 僵尸键 |
| `TestEngineIntegration` | 6 | **裁判模式池必须生效**；换边重置；全局 `di/sumall` 不变量；多回合端到端 |
| `TestEvalImpact` | 5 | `average` 表 / `possible_che` / `value()` 的实际变化；float 池不破坏 `calc_average` |

三个边界情形值得单独点出，它们是我在写测试时才想清楚的：

- **暗子走动后立刻被吃** → 真身永不可知。测试断言 `rev` 不臆测、但池大小仍正确。这是信息论下界，不是 bug。
- **所有类型都已翻开满但盘面仍有朝下子**（识别矛盾）→ 退回先验，绝不返回全 0。否则 `sumall == 0` 会让 `value()` 分母为零。
- **明子被吃后 `rev` 不得回落** → 正是 v5.11 的错误所在，单独锁死。

测试期间发现并修正了自己的两个错误：最初 3 个 `TestEvalImpact` 用例把「已翻开的子」留在盘面上，而那恰好是 v5.11 能正确处理的情形，用例因此无区分力；`GAMES` 的 glob 会吞掉对局套件产出的汇总 JSON（schema 不同）。

## 四、对局结果

三组实验，全部 1.0s/着、PyPy 3.11、等墙钟。

### 4.1 主实验：10 局交替先后手

```
战绩 (P0 视角): 7胜 2负 1平   得分 7.5/10 = 75%
  P0 执红: 4胜 0负 1平
  P0 执黑: 3胜 2负 0平

用时/着  P0 0.736s  v511 0.729s   (偏差 1.0%)
平均深度  P0 5.78    v511 5.79     (差 -0.01)
终局: 吃王 ×9, 重复判和 ×1;  平均 66 着
```

算力对称性合格：用时偏差 1.0%、深度差 −0.01，**胜负不来自多算**。

符号检验：决胜 9 局，双侧 p = 0.18 → 未达 0.05 显著。

### 4.2 扩展到 20 局

第二批（不同种子）5胜 4负 1平，明显弱于第一批。合并 20 局：

```
12胜 6负 2平 = 65%    双侧 p = 0.24 (仍不显著)
Elo 点估计 +108 (95% CI -41 … +314)

按颜色拆分:  P0 执红 90% | P0 执黑 40%
按颜色统计:  红方胜 14, 黑方胜 4  → 红先方得分 75%
```

最后一行是关键发现：**揭棋先手优势在本样本中是最强的单一因素**，远强于引擎差异。颜色在设计上是平衡的（各 10 局），所以 65% 这个总数无偏，但它的方差几乎全部来自「这一局谁执红」和「暗子怎么洗」，信号被淹没。

### 4.3 配对对局（消除颜色与布局方差）

于是改用配对设计：同一暗子布局打两遍，两引擎各执红一次。

```
逐局战绩: 10胜 9负 1平 = 52.5%
配对结果: P0 净胜 3 对 | 净负 2 对 | 打平 5 对

颜色效应校验: 红方胜 10/19 决胜局 (53%)   ← 对比未配对的 75%, 混淆因素确已抵消
用时/着 P0 0.727s vs v511 0.727s (偏差 0.0%)
平均深度 P0 5.92 vs v511 5.85    (差 +0.07)
```

**配对后优势消失（52.5%）。** 这是三组数据里最可信的一组，因为它把最大的两个方差源成对抵消了。前两批的 75% / 65% 应理解为颜色与布局运气的产物，不是棋力证据。

## 五、为什么正确性修好了，棋力却测不出

我做了一个直接的诊断，而不是猜：在 180 个真实对局局面上固定搜索预算，只改变暗子池，看引擎选择是否改变。

```
阶段              局面数   选择改变   池误差 v511   池误差 P0
开局(<20着)          60      1/60         1.58        0.00
中局(20-60)          60      7/60         7.33        0.00
残局(>60)            60      5/60         9.95        0.00
合计: 13/180 = 7.2% 的局面选择发生改变
```

**只有 7.2% 的局面选择改变。** 原因是池只影响两个次要项 —— `average` 表（暗子期望值）和 `possible_che`（暗车期望数），而评估主项是 PST + 明子子力。多数局面下着法排序不变。

配上样本量测算：

| 真实优势 | 需要局数（α=0.05, power=0.80） |
|---|---|
| +10 Elo | ~7670 局 |
| +20 Elo | ~1921 局 |
| +50 Elo | ~311 局 |

20 配对局的可分辨下限约 **222 Elo**。一个只改变 7.2% 决策的次要项修复，其效应量必然远低于这个分辨率。**「测不出显著性」是这个效应量与这个样本量的算术必然，不是实现失败。**

诚实的表述是：本次修复的价值在于**正确性与最坏情况有界**，而非可测的即时棋力增益。我不会把 75% 当作战果汇报 —— 配对实验已经证明它主要是颜色运气。

另一个不该忽略的点：池误差在**残局**最大（v5.11 平均 9.95 个幽灵子），而残局恰恰是暗子最少、`covered` 因子最小的阶段，所以巨大的相对误差乘上很小的权重，绝对影响被稀释。这解释了为什么一个 78% 的误差削减只换来 7.2% 的决策变化。

## 六、这次修复的真实价值

不在胜率，在三处：

1. **消除了静默失真**。原实现的误差随对局进行单向累积（被吃明子越积越多），且无任何断言会发现。现在有硬不变量。
2. **为 P1/P2 提供正确先验**。P1（U 解冻确定化抽样）和 P2（机会节点分叉）都直接按池概率抽类型 —— 池错，后两步的概率分叉全是错的。P0 是它们的必要前置，其收益会在 P2 落地后才真正兑现（那时池不再是次要项，而是分叉概率本身）。
3. **修掉了会让所有后续 A/B 失效的 `live` 门控**。这一处如果不改，P1/P2 的裁判模式实验会全部测不到自己的改动。

## 八、建议的下一步

1. **后续 A/B 统一用配对设计**（`run_p0_paired.py`）。未配对实验在这个项目里方差太大：同样的两个引擎，两批 10 局给出 75% 和 55%。
2. **P1（U 解冻）优先于继续调池**。U 冻结影响 75% 的子（24 半步后）、能伪造无着可走、且会漏看对手翻子后的反击 —— 效应量远大于 7.2%，20 局配对就有希望测出来。
3. **P1 落地后重测 `depth ≥ 12` 上限**（`jieqi_engine.py:630`）。该上限的注释理由是「贪吃诱导」，而贪吃的根源正是 U 冻结带来的「敌方翻开的子不会还手」偏差。修好 ① 之后这个创可贴可能可以摘掉，但必须单独作为一个变量测。
